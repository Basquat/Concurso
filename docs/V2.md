# Concurso Lab 2.0 — plano e decisões

Documento vivo: arquitetura, convenções e checklist da versão 2.0. Atualize ao concluir cada item.

## Princípios

1. **Tecnologia real sempre que o navegador permitir.** Python (Pyodide), PostgreSQL 17 (PGlite), SQLite (sql.js),
   PHP 8.4 (php-wasm), Java (CheerpJ, carregado do CDN da Leaning Technologies — licença Community, exige crédito),
   React/Vue/Babel reais no executor isolado, editor Monaco (o mesmo do VS Code), BPMN (bpmn-js), diagramas (Mermaid),
   criptografia (Web Crypto). Quando não há como executar (Docker, Kubernetes, roteadores), o simulador segue a
   semântica documentada da ferramenta (mesmos comandos, mesmas mensagens, mesmos formatos de arquivo).
2. **Tudo estático (GitHub Pages).** Sem build obrigatório; módulos ES carregados sob demanda.
3. **Cada laboratório diz o que é real e o que é simulado.**
4. **Conteúdo ligado ao edital.** Aulas, questões e laboratórios apontam para itens do programa do cargo.
5. **Segurança de verdade no que é possível sem servidor** (cofre cifrado) e sincronização opcional com backend
   configurável (Supabase) com criptografia de ponta a ponta.

```
  application/        serviços (estudo, revisões, plano)

    storage/          IndexedDB, cofre cifrado (AES-GCM), contas, migração da 1.0, nuvem (Supabase)

    runtimes/         executores reais (js/ts, python, php, java, sql, postgres)

```

## Contas e segurança

- **Cofre local cifrado.** Cada conta tem uma chave de dados (DEK, AES-GCM 256) aleatória. A DEK é guardada
  "embrulhada" duas vezes: pela senha (PBKDF2-SHA256, 600 mil iterações, sal de 16 bytes) e pelo código de
  recuperação (160 bits, exibido uma única vez). Cada registro é cifrado com IV próprio e AAD `conta:chave`.
- Senha errada = falha de autenticação do GCM (não há hash comparável guardado).
- Bloqueio progressivo após 5 falhas; histórico de acessos; bloqueio automático por inatividade;
  "manter conectado" guarda a chave como CryptoKey **não extraível** no IndexedDB (30 dias).
- Visitante: dados sem cifra, migráveis para uma conta.
- Migração automática dos dados da 1.0 (localStorage) no primeiro acesso.
- **Nuvem opcional (Supabase):** e-mail/senha com JWT, linhas protegidas por RLS e conteúdo cifrado de ponta a ponta
  (o servidor só vê texto cifrado). Ver `docs/NUVEM.md`.
